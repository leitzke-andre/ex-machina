# Community Bitwig controller scripts for the Maschine Mikro MK3 (and close relatives)

Research date: 2026-10-21. Primary sources: DrivenByMoss source code and documentation on GitHub (read directly from the `master` branches), GitHub repository metadata via the GitHub API, KVR forum threads, NI blog. Paths to DrivenByMoss sources below are relative to `https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/`.

## Which projects exist, their status, last updates and licence

### Takeaway
There is effectively one maintained Bitwig integration for the Mikro MK3: the "Maschine Mikro Mk3" controller in Jürgen Moßgraber's **DrivenByMoss** (LGPL-3.0, active, release 26.6.5 of 2026-09-04, commits up to 2026-10-21). Everything else is either for older Maschines (Mikro MK1/MK2, MK1/MK2, Studio; abandoned 2015-2021), for the Maschine JAM (MonsterJam, active), for the full Maschine MK3 over raw HID (Embit, 2026), or empty placeholder repositories (two 2026 "Mikro MK3 Bitwig Linux" repos with no content).

### Cited Findings
**DrivenByMoss (the only real Mikro MK3 option)**
- Repository `git-moss/DrivenByMoss`, licence LGPL-3.0, last push 2026-10-21, ~808 stars — [GitHub API repo metadata](https://api.github.com/repos/git-moss/DrivenByMoss); [repo](https://github.com/git-moss/DrivenByMoss)

### Inferences
- For the Mikro MK3 specifically, "community Bitwig integration" in practice means DrivenByMoss; it is the only one that is complete, documented, licensed and maintained in 2026.
- The empty DavidLanas repos suggest demand for a Linux path (DrivenByMoss does not run on Linux for NI devices; see the last section), combining a HID driver such as r00tman's with a Bitwig script, but nothing usable has been published.

### Gaps
- No Reddit r/Bitwig threads about Mikro MK3 scripts surfaced in search; user experience reports are limited to KVR and NI forum posts, mostly 2019-2021.
- The DrivenByMoss manual PDF was not opened; the Markdown documentation and source code were used instead (they are the source of the PDF).
- Whether "the native one of Bitwig 6" (DavidLanas description) refers to a Bitwig-bundled Maschine script could not be verified.

## Modes and features implemented (DrivenByMoss Mikro MK3 in detail)

### Takeaway
DrivenByMoss gives the Mikro MK3 a compact Push-style workflow: pads switch between Scene launch, clip launch (Pattern), device-parameter select (Variation), track Select/Solo/Mute, Drum mode with a 16-step sequencer and note editing, and Play mode with scales and chords; the single encoder is a modal "value knob" (volume/pan/sends, position, tempo, device parameter, browser); the strip is pitch/mod/master volume/note-repeat; Stop doubles as Shift. Its well-designed ideas are bank paging by "hold the mode button and turn the encoder", Stop+pad edit shortcuts, and blinking pads for selected/muted/soloed state.

### Cited Findings
**Global and transport** (all from [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md))
- Sampling: Slice to Drum Machine dialog; Stop+Sampling: Slice to Multi-sample.
- Group: creates a new clip on the selected track/slot, starts playback and enables overdub.
- Auto: arranger automation write; Shift+Auto: clip launcher automation write. Lock: arranger overdub; Shift+Lock: launcher overdub (a preference flips arranger/launcher roles).
- Note Repeat: toggles note repeat; long press enters a configuration mode where pad columns 1-2 set the period and columns 3-4 the note length.
- Play: start/stop, double-press returns to song start; Rec: record; Stop: stop, or move cursor to start when stopped; Restart/Loop: transport loop; Erase+pad: delete scene/clip/track depending on mode; Erase+touch encoder: reset value to default; Tap: tap tempo; Stop+Tap: metronome; Follow: step-sequencer grid resolution page.
- Browser: Project = add instrument track (or discard while browsing), Stop+Project = save; Favorites = browser to add a device; Browser = browse current device (or insert), with Pattern pad = browse clip; in the browser the encoder scrolls and an encoder press confirms.
- Undo/redo and clip edits on Stop+pad: Stop+Pad1 undo, Pad2 redo, Pad5 quantize 100%, Pad6 quantize 50%, Pad9 clear all notes, Pads 13-16 transpose -1/+1/-12/+12 — [ShiftView.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/view/ShiftView.java); [KVR 10.1 changelog](https://www.kvraudio.com/forum/viewtopic.php?p=7822774)

**Encoder modes** ([Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md))
- Volume: volume / pan / sends of the selected track, press Volume again to cycle; encoder press toggles fast/slow.
- Swing: play-cursor position (source also registers loop start / loop length modes on this button) — [MaschineControllerSetup.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/MaschineControllerSetup.java)
- Tempo: tempo, press again for fine; pressing the encoder repeatedly taps tempo.
- Plug-In: one device parameter (selected via Variation pads); Stop+Plug-In toggles the plug-in window.
- Encoder touch is used (touch + Erase resets to default); the encoder sends relative values on CC 7, push on CC 8, touch on CC 9 in the template — [MaschineControlSurface.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/controller/MaschineControlSurface.java)
- Fixed Vel + turn encoder sets the fixed velocity value.

**Pad modes**
- Scene: launch one of 16 scenes of the bank. Pattern: launch one of 16 clips of the selected track; Pattern+pad stops. Variation: select one of 8 device parameters (pads in Bitwig parameter colours, selected blinks), pads 13/14 select the device, 15/16 the parameter page. Duplicate+pad: duplicate scene/clip/track. Select / Solo / Mute: 16 tracks of the bank, the selected/soloed/muted ones blink — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md)
- Bank paging: hold Scene / Pattern / Select / Solo / Mute and turn the encoder — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md)
- Because the Mikro has no group buttons, the model uses a 16-track bank (8 on models with group buttons) and 16 scenes; separate SelectView/SoloView/MuteView pad views exist only for such devices — [MaschineControllerSetup.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/MaschineControllerSetup.java)
- Drum mode (Pad Mode): second press opens a configuration page (pads 15/16 transpose). Step: 16-step sequencer of the selected drum cell. Follow: grid configuration (lower 8 pads = resolution, pads 13/14 = edit page). Events: select note(s) by pad and edit their parameters with the encoder; Volume/Swing/Tempo (pressed once or twice) choose among six note parameters. Mute+pad mutes a step (shown grey) — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md)
- Play mode (Keyboard): second press opens configuration: pad 1 chromatic/in-scale, 5/6 layout, 9/10 root, 13/14 scale, 15/16 octave. Step sequencer of the last played note works here too. Chords: each pad adds two stacked thirds; the second visible octave plays inversions — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md). Default layout since 10.1 is "Sequential up" — [KVR](https://www.kvraudio.com/forum/viewtopic.php?p=7822774)
- Preferences: behaviour on pause, flip arranger/launcher record and automation, fixed accent and value, quantize amount, ribbon mode, select clip on launch, action for rec-armed empty clip, exclude deactivated items, new clip length. Per-project: scale, base, in-key/chromatic, layout, note-repeat active/period/length/arp mode/octave — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md)

**Touch strip** ([Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md); [TouchstripCommand.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/command/continuous/TouchstripCommand.java); [RibbonMode.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/RibbonMode.java))
- Eight ribbon modes chosen by the strip buttons: Pitch (repeated presses: Down / Up / Down-Up), Mod (CC 1, again for CC 11 Expression), Perform = master track volume, Notes = note-repeat period (again: note length).
- Pitch Down maps the strip to (127-v)/2, Pitch Up to 64+v/2, Down/Up to the full range; pitch modes spring back to centre on release, CC/volume/note-repeat modes do not.
- The strip arrives on CC 1, its touch on CC 2; the script writes the current value back on CC 1 so the strip LEDs show the master volume or note-repeat rate.

**What is not available on the Mikro in DrivenByMoss**
- The hardware Shift and the cursor (encoder-direction) buttons send no MIDI in NI's MIDI mode, so Stop is the Shift substitute — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md); [Maschine.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/Maschine.java) (`MIKRO_MK3(..., hasShift=false, hasMCUDisplay=false, hasGroupButtons=false, hasCursorKeys=false, ...)`)
- No user mode (needs the MCU display) and no 8 display knobs (Mikro has only one encoder) — [MaschineControllerSetup.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/MaschineControllerSetup.java)
- A user found per-pad MIDI channels impossible with the script; the author pointed to Bitwig's per-track input channel instead — [KVR](https://www.kvraudio.com/forum/viewtopic.php?p=8277039)

**Relatives: ideas worth noting**
- Maschine MK3 (same codebase) adds 8 display knobs with Volume/Pan/Send/Remote-page/Device modes, page left/right through clips, VU-meter toggle, Shift+Solo/Mute clears all — [Mk2/Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mk3.md)
- MonsterJam (JAM): retroactively quantised ("lenient") clip launch, SuperScenes (snapshot of playing clips onto a scene button), "auto-gating" mode buttons (short press toggles, long press is momentary), Control Slice (one parameter across all tracks), "MonsterFX" perform remote page set to 1 while the strip is touched, step sequencer with per-step velocity/length/pan/timbre/pressure, 16 scales where changing a scale hides out-of-scale notes rather than re-transposing — [MonsterJam docs](https://github.com/unthingable/monster-jam/blob/master/docs/README.md)
- Embit (MK3, HID): mixer view with track colours, VU meters, M/S/arm flags; channel view; device view showing modulated parameter values; transport with Shift+Rec count-in — [Embit README](https://github.com/RufusIbiza/encdr-maschine-bitwig)
- Mikro MK2 script (SoundDevelopment): four encoder modes Track / View (zoom) / Edit (cut/copy/paste, encoder = playhead) / Control; encoder press = Enter; pad groups labelled by note range with special colours for C1-D#2 and C3-D#3; pads light with intensity matching the velocity of incoming notes — [README](https://github.com/SoundDevelopment/machine_mikromk2_bitwig3_script)

### Inferences
- With only one encoder and no usable Shift, DrivenByMoss leans on "hold button + turn encoder" and "Stop + pad" chords; these are directly reusable ideas for an FL Studio script on the same hardware.
- The Mikro covers clip/scene launching, drum sequencing, scales and single-parameter device control well, but mixer work is one track at a time (encoder) since there are no multiple knobs.

### Gaps
- No list of the "six note parameters" in Events mode beyond the doc's description; would need `EditNoteMode.java`.
- No independent user reviews comparing DrivenByMoss's Mikro MK3 workflow with alternatives were found.

## Display and LEDs

### Takeaway
In DrivenByMoss the Mikro MK3's monochrome screen is **not used** (no host-writable display in NI's MIDI mode for this model); feedback is pad and button LEDs only. Pads use NI's MIDI-mode colour palette (indexed values), clips show the Bitwig clip colour with green/red for play/record, button LEDs are effectively on/off. HID-level projects show the hardware can do more (4 brightness levels per button LED, screen).

### Cited Findings
- `MIKRO_MK3` has `hasMCUDisplay=false`; an MCU-protocol text display is created only for models that support it (Mk2, Mk3, Maschine+, Studio) — [Maschine.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/Maschine.java); [MaschineControllerSetup.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/MaschineControllerSetup.java)
- Pads are a 4x4 grid starting at note 36 — [MaschinePadGrid.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/controller/MaschinePadGrid.java)
- Colour indices used for pads (NI Controller Editor palette): black 0, red-lo 5 / red 6 / rose 7, orange-lo 9 / orange 10 / skin 11, amber-lo 13 / amber 14, yellow-lo 21 / yellow 22, spring 25-26, turquoise 27/31, green-lo 29 / green 30, lime 33-34, sky 37-38, blue 42 / blue-lo 45, purple 50/53, magenta 57-58, pink 61-62, dark grey 76, grey 77, white 78 — [MaschineColorManager.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/MaschineColorManager.java)
- Bitwig's 26 track/clip colours are mapped to these indices (e.g. Bitwig red → 6, orange → 10, light orange → 22, green → 26, cold green → 31, blue → 42, light blue → 38, purple → 50, pink → 62, greys → 76/77) — [MaschineColorManager.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/MaschineColorManager.java)
- State colours: step-sequencer content blue (continuation blue-lo), playhead step green / green-lo, selected step yellow, muted step grey/dark grey; drum pads: playing green, recording red, selected blue, muted amber, has content lime, empty dark grey; scale play view: root (octave) blue, in-scale white, out-of-scale off; browser confirm green / discard red — [MaschineColorManager.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/MaschineColorManager.java)
- Clip view: record-queued red-lo, recording red, play-queued green-lo, playing green, stop-queued green-lo, otherwise the clip's Bitwig colour, empty off — [ClipView.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/view/ClipView.java)
- Blinking is used for selection state (selected track, selected parameter, soloed/muted tracks blink); Variation pads use Bitwig's eight parameter colours (red, amber, yellow, green, lime, sky, purple, pink) — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md); [MaschineColorManager.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/MaschineColorManager.java)
- Button LEDs: "on" and "off" both map to value 0 and "hi" to 127, i.e. buttons are lit only when active — [MaschineColorManager.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/MaschineColorManager.java); LED feedback is sent as CC on the button's CC (one exception sent as a note) — [MaschineControlSurface.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/controller/MaschineControlSurface.java)
- Touch strip LEDs reflect ribbon state (master volume or note-repeat value) via CC 1 output — [TouchstripCommand.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/command/continuous/TouchstripCommand.java)
- Pressing Stop resends the full display/button state (useful after entering MIDI mode); the device also sends a SysEx `F0 00 21 09 <id> 4D 50 00 01 46 01 F7` on returning to MIDI mode, on which the script forces a full LED flush (`<id>` = `17 00` for the Mikro) — [KVR 10.1 changelog](https://www.kvraudio.com/forum/viewtopic.php?p=7822774); [Maschine.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/Maschine.java); [AbstractMaschineControlSurface.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/AbstractMaschineControlSurface.java)
- At HID level the r00tman driver drives LEDs and the screen, can turn unpressed pad LEDs fully off, and found that "every button has 4 levels of brightness, not just Off/On as in the official MIDI Mode" — [r00tman README](https://github.com/r00tman/maschine-mikro-mk3-driver)
- On the MK3, Embit renders full-colour 480x272 Svelte UIs to both screens from a Rust daemon — [Embit README](https://github.com/RufusIbiza/encdr-maschine-bitwig); MonsterJam colours track buttons by track colour, scene buttons by scene colour, playing at full brightness, and device-selector pads by device type (native audio FX orange, native instrument yellow, note FX cyan, plugin audio FX magenta, plugin instrument lime, plugin note FX plum) — [MonsterJam docs](https://github.com/unthingable/monster-jam/blob/master/docs/README.md)

### Inferences
- The colour index pattern (e.g. 5/6/7, 9/10/11, 13/14, 21/22, 29/30, 61/62) is consistent with NI's MIDI-mode palette of 16 hues × 4 brightness steps plus whites at 76-78; DrivenByMoss uses the "lo" step for queued/continuation states and the full step for active states.
- Since the Mikro has no MCU display, DrivenByMoss's `display.notify(...)` messages (e.g. "Undo", "Quantize: 50%") probably appear only as Bitwig on-screen popups, not on the device (not verified in the framework code).

### Gaps
- Whether NI's MIDI mode lets a host write text to the Mikro MK3 screen at all was not confirmed from a primary NI source; the DrivenByMoss model flag only shows that the script does not try.
- The exact NI palette (hue names per index block) is not documented in the sources read.

## How they talk to the hardware (HID vs MIDI mode, NI drivers / NIHIA)

### Takeaway
DrivenByMoss uses NI's **MIDI mode** (Controller Editor template, Shift+Project to enter on the Mikro), so it needs NI's driver/background services and only works on Windows and macOS, not Linux or Windows on ARM. HID-based projects (r00tman driver, Embit for MK3) bypass NI software, gain full LED/screen control, but must stop NI's services from claiming the device.

### Cited Findings
- "Since the extension requires the Native Instruments Host Integration service it only works on Windows and Mac (no Linux)"; install the template from `resources/Maschine Mikro Mk3` with NI Controller Editor; "This extension uses the MIDI mode of the device. Press Shift + Project ... to enter MIDI mode" — [Mikro Mk3 doc](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/Native-Instruments/Native-Instruments-Maschine-Mikro-Mk3.md)
- The template had to be reloaded once because of touch-strip setting changes ("load this new template ... first"); it is shipped as a template (`.ncmm3`) rather than a full memory dump (`.ncc`) — [KVR](https://www.kvraudio.com/forum/viewtopic.php?p=7822707)
- On Windows on ARM all NI controllers, including the Mikro Mk3, "miss MIDI drivers and therefore do not work" — [DrivenByMoss KnownIssues.md](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/KnownIssues.md)
- Windows error "Could not open MIDI output. There is not enough Memory" means another process holds the port; for NI devices check the NI background services — [KnownIssues.md](https://github.com/git-moss/DrivenByMoss-Documentation/blob/master/KnownIssues.md)
- The script filters note on/off (`80????`, `90????`) from the "Maschine Mikro Mk3" input into Bitwig's note input; everything else is CC: strip CC 1/2, encoder CC 7/8/9, buttons CC 22-111 per the template (e.g. Play 57, Rec 58, Stop 59, Pad Mode 81, Keyboard 82, Step 83, Chords 84, Scene 85, Pattern 86, Events 87, Variation 88, Duplicate 89, Select 90, Solo 91, Mute 92) — [MaschineControllerSetup.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/MaschineControllerSetup.java); [MaschineControlSurface.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/mk3/controller/MaschineControlSurface.java)
- NI's MIDI mode reports Shift on models that support it as SysEx `F0 00 21 09 <id> 4D 50 00 01 4D 01/00 F7` (down/up); the Mikro is flagged as not having a usable Shift — [Maschine.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/Maschine.java); [AbstractMaschineControlSurface.java](https://github.com/git-moss/DrivenByMoss/blob/master/src/main/java/de/mossgrabers/controller/ni/maschine/core/AbstractMaschineControlSurface.java)
- Channel and poly aftertouch of the pads were later routed to Bitwig — [KVR](https://www.kvraudio.com/forum/viewtopic.php?p=8277039)
- A user had trouble leaving MIDI mode / switching templates; the author called it a likely Maschine hardware bug, worked around by enabling "Knob pages" (which then disables the arrow buttons for DrivenByMoss) — [KVR](https://www.kvraudio.com/forum/viewtopic.php?p=7822774)
- Embit talks USB HID directly via the `encdr` library from a Rust daemon, with a thin Bitwig JavaScript script (API 25, Bitwig 5.1+) exchanging state over OSC/UDP; on Windows/macOS NI services (`NIHardwareHelper.exe`, `NIHostIntegrationAgent.exe`) "may claim the USB interface" and must be stopped; on Linux a udev rule for VID 17cc — [Embit README](https://github.com/RufusIbiza/encdr-maschine-bitwig)
- r00tman's Linux driver talks HID with a udev rule and exposes an ALSA/JACK MIDI port named "Maschine Mikro Mk3 MIDI Out"; its stated goal is to reimplement the official MIDI mode, with modal Maschine-style functions "not yet planned" — [r00tman README](https://github.com/r00tman/maschine-mikro-mk3-driver)
- MonsterJam also needs NI drivers and runs on Mac and Windows only — [MonsterJam docs](https://github.com/unthingable/monster-jam/blob/master/docs/README.md)

### Inferences
- MIDI-mode scripts inherit NI's limits: no Shift, no cursor buttons and no screen on the Mikro, two-level button LEDs, and dependence on NI's driver stack. A class-compliant firmware with its own MIDI map (as in this repository) removes the driver dependency and could expose Shift, the screen and LED brightness levels to a DAW script, which no existing Bitwig script for the Mikro does.
- A Bitwig script for a class-compliant Mikro could reuse DrivenByMoss's mode design while replacing the template CC map; DrivenByMoss's LGPL-3.0 licence allows reuse with conditions.

### Gaps
- Whether DrivenByMoss's Mikro extension really needs NIHostIntegrationAgent at run time (versus only the NI USB MIDI driver) is stated in the doc but not explained; no primary NI source on the MIDI-mode driver path was checked.
- No source documents the Mikro MK3 MIDI-mode SysEx set (beyond the shift/return messages above) or whether the screen accepts host text in MIDI mode.
