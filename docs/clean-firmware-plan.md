# Towards a firmware without NI code

Goal: an Ex-Machina image that contains none of NI's bytes, so that it can be published and flashed without the user's own copy of NI's firmware. Decided on 2026-10-19: **not a clean-room rewrite** but a step-by-step replacement inside the hybrid image we already flash, because every step then has a known-good image to fall back to. NI's code may be read to replace it; what replaces it is our own code. NI's bootloader (`0x08000000-0x08002FFF`) stays on the device and is never part of an image.

## Rules for every step
- A new image goes on top of the last known-good one; a stock piece is removed only after its replacement works on the device.
- **Outputs** (LEDs, display) get a run-time switch between our driver and the stock one (stock by default until ours is proven).
- **Inputs** (buttons, encoder, strip, pads) run in **shadow mode** first: our scan runs next to the stock one, a debug command reports the differences, and nothing depends on ours until they match.
- Every image keeps the safety features of stage 0 and is tested in the emulator before it is flashed.

## Stage 0: safety (no NI code is replaced)
- **Crash-loop guard**: the patch starts the watchdog at its first instruction (about 26 s, until the stock init sets its own 1 s), and counts consecutive watchdog resets in RAM that survives a reset (`0x20004FF0`: magic, count, ~count, the last RCC_CSR). After 3 in a row the firmware writes the bootloader's DFU request into the handshake page and resets: the device comes up in DFU mode (`17cc:1702`) and stays there until an image is flashed. Any other reset cause (power-on, software reset after a flash) starts the count over, and 10 s of normal running clear it.
- **Boot gesture**: holding **Shift + Stop + Erase** for 2 s shows `DFU MODE` and enters the bootloader the same way (for a device whose USB no longer answers but whose buttons still work).
- **Handshake facts** (read on the device 2026-10-19): the app requests DFU by writing `55 5A A5 AA 59 95 3A A3` at `0x0801FC00` (rest of the page erased) and resetting; after a successful flash the bootloader leaves `59 95 3A A3 55 5A A5 AA` there (the two words swapped) and starts the app.
- **Still needed from the user**: whether the board has SWD pads (opening the unit), and ideally an ST-Link: the only recovery if an image hangs before the patch's first instruction runs.

## Stage 1: recon (read-only)
- `PEEK` extended to the configuration registers of the peripherals (RCC, GPIO, AFIO, ADC, DMA, timers, SPI, I2C, IWDG, USB, NVIC, SysTick, SCB; data registers with read side effects are excluded). `tools/probe_chip.py --peripherals` prints how the stock firmware configured the chip.
- Raw pad capture: a SysEx command records the 16 raw ADC channels on every main-loop pass into free RAM (`0x20001C20`, 512 frames), read back with `PEEK`; the base for our own pad algorithm.
- The strip, LED and display protocols, specified from emulator traces of the stock code.

## Stage 2: take over, leaf first
1. Our own main loop, calling the stock routines as black boxes.
2. LED driver (with the per-LED trim in NI's settings page A, which is device data and stays).
3. Display sender.
4. Buttons and encoder scan.
5. Touch strip (bit-banged I2C).
6. Pad scan and hit / pressure algorithm (tuned against the raw captures and the stock output).
7. USB stack, board init, flash routines and the DFU detach, last.

Then the remaining stock bytes are dropped, the browser tool builds nothing from the user's NI image, and the firmware gets its own USB vendor / product ID.
